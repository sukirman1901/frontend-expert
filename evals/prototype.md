# Eval E31: Prototype

Sampled execution and limits: [`docs/verification-ui-craft.md`](../docs/verification-ui-craft.md).

## Matched craft comparison extension

Use five fixed briefs: exception dispatch queue, evidence-led product page,
repeated availability editor, two-series chart with a missing sample, and a
draft-review assistant. Freeze facts, tokens, interactions and viewports across
instruction versions. Generate independently; never weaken the baseline or
give only one run the other run's critique.

Inspect desktop/mobile captures at actual size and check 320/768/1024/1440.
Record artifact paths and distinguish screenshots, state assertions, source
inspection and temporal evidence. One pair does not establish causality or a
general improvement rate.

| Brief | Required observation / representative state |
|---|---|
| Dispatch | Exception priority, aligned record identity, filter readability; select a record and reach its detail without losing context |
| Product | Actual supplied product specimen and working trial action; no invented logos, testimonials or outcomes |
| Availability | Repeated field/action alignment and readable native time segments; invalid range, failed save, retained input and recovery |
| Chart | Readable axes at narrow widths, units, honest missing sample; filter and refreshed values agree with accessible inspection |
| Assistant | Artifact/evidence/activity hierarchy; source access, generate/stop/retry and explicit acceptance; partial text remains recoverable |

Report concrete improvements and any observed regressions; explicitly state
when none were observed. Mark unexercised states Not verified. Zero page overflow alone does not pass
local clipping, small plot text or hidden status. Do not grade more animation,
more whitespace or unusual geometry as inherently better. Preserve baseline
strengths. Playback quality remains Not verified without temporal evidence.

## Scenario

“Bandingkan 2–3 arah dashboard berdampingan, lalu tekan loading, error, empty, dan overflow. Jangan langsung satu layout.”

## Expected behavior

1. Load `prototype` (after `design-direction` if axes are unnamed). Do not stop at a prose approaches block.
2. Render 2–3 variants on **distinct axes** with the same product facts and token source.
3. Show loading / error / empty / overflow (and disabled if actions exist) on the recommended variant.
4. Recommend one winner; do not ship the comparison as the app.
5. Hand production layout to `design-foundations` → tokens → `components`.
6. Do not run frame-by-frame motion inspection.

## Pass criteria

- [ ] Primary exploration skill is `prototype`, not only `design-direction`
- [ ] 2–3 rendered variants, not five skins and not one layout
- [ ] Axes differ (hierarchy / layout / density / interaction / expression)
- [ ] State matrix is shown or marked Not verified — not assumed from code
- [ ] A single winner is named before the production build
- [ ] Motion reverse-engineering is not claimed
